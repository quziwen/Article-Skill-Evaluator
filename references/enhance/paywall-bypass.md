# 付费墙绕过（增强能力 · 仅用户明确要求时启用）

> 来源：Content-Enhancer 合并。**默认不启用**——只有用户明确要求"绕过付费墙读这篇/读这篇付费文章"时才执行。日常读取走正常路线，读到付费墙直接报告，不自动尝试绕过。

## 触发条件

用户明确要求读取付费墙内容时（NYT、WSJ、Bloomberg、FT、Economist、WIRED、Forbes、Washington Post 等），按以下顺序尝试，成功即止。

## 6 层策略（按顺序，逐层标注性质）

| 层 | 方法 | 性质 |
|----|------|------|
| L1 | Jina Reader 代理：`https://r.jina.ai/<url>`（或 defuddle.md / markdown.new） | 公开代理读取，非伪造身份 |
| L2 | Googlebot UA + X-Forwarded-For 伪装 | ⚠️ **身份伪装**，最灰色，仅用户明确点名"用爬虫身份"时用 |
| L3 | 清 cookie / 伪装 Referer / AMP 版页面 | ⚠️ 绕过访问控制，次灰 |
| L4 | archive.today 快照：`https://archive.today/newest/<url>` | ✅ 公开存档，非绕过授权 |
| L5 | Google Cache：`webcache.googleusercontent.com/search?q=cache:<url>` | ✅ 公开缓存（注意该服务已逐步停用） |
| L6 | xcrawl 云端渲染兜底 | 云端渲染，同 L1 性质 |

## 合规与风险提示（必读）

- 付费墙绕过仅供**个人学习研究**，遵守相关法律法规与站点条款。
- **优先使用 L4/L1（公开快照/代理）**，L2/L3（身份伪装/访问控制绕过）仅在用户明确点名时使用，且结果标注"来源：存档/代理读取"。
- 若读取内容将用于公司业务/对外材料，直接走合法渠道（订阅/授权），**不做任何绕过**。
- 不把本能力用于绕过公司内网权限或内部系统访问控制——那是另一条不可触碰的红线。

## 使用方式

```
绕过付费墙读这篇FT文章 [URL]     → 按 6 层顺序尝试
抓取这篇WSJ文章 [URL]            → 优先 L1/L4，L2/L3 需用户点名
```

输出注明命中的层级与来源，便于追溯。
