# 文章转播客

将已取得的文章改写为开场、章节要点、收尾的口播稿。事实、数字、作者观点和证据缺口与原文保持一致，不添加虚构案例。

## 工具调用契约

1. 查询当前宿主已提供的工具或已安装的本地 TTS 程序，读取其真实 schema 或帮助。`text_to_speech` 仅是能力名称，不是每个宿主都存在的工具；不得凭名称构造调用。
2. 确认工具接受的文本、语言/声音、输出路径、格式和时长限制。将正文生成的口播稿传入其实际文本参数；优先用户指定声音，否则沿用工具默认值并说明。工具只提供 WAV 时交付 WAV，不改后缀冒充 MP3。
3. 仅使用本次允许的数据处理路线。本地工具按已安装帮助调用；云端工具需本次允许将正文发送至该服务，不自动注册、安装程序、申请密钥或变更配置。
4. 用户已指定保存目录就使用该目录；未指定时先在对话交付口播稿，再问保存目录，暂停音频文件写入。不默认用桌面或其他猜测目录。已有文件默认不覆盖。
5. 调用成功后回读实际产物：核对返回路径、文件存在且非空、实际音频格式与返回格式一致，并用当前可用播放器或音频探测器检查可解码及持续时间。未做的检查标记未验证；不能仅凭成功消息声称可播放。

## 缺能力与失败处理

- 工具列表或本机程序中没有 TTS：标明 TOOL_MISSING、音频未生成，在对话交付可录音的口播稿。列出缺少的 TTS 能力；不要让用户重复提供已有正文。
- 当前任务禁止外部调用且无本地 TTS：直接按上述缺能力分支，不联网探测或安装。
- 有工具但缺输出目录：保留口播稿，仅询问保存目录；不落盘。
- 服务拒绝、超时或生成失败：保存实际错误类别，明确未确认音频成功；不自动重复付费调用。已存在部分文件时报告路径与状态，不覆盖或冒充完整产物。
- 工具不能提供所需格式：说明实际支持格式，先交付口播稿，不暗中安装转码器。

## 完成说明

分别报告口播稿是否完成、音频是否实际生成、实际格式/路径、可播放检查及未验证项。只交付了稿件时明确说“播客稿已完成，音频未生成”。
