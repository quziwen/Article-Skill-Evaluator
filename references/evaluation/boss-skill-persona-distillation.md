# Boss Skill / 人物蒸馏 — 将人转化为 AI Skill

## 来源

## 什么是人物蒸馏？

人物蒸馏（Persona Distillation）是将一个人的决策模式、沟通风格、思维框架提取出来，封装成 AI Skill 的过程。不同于传统的"技能蒸馏"（把工作流程变成 Skill），人物蒸馏的目标是复现一个人的"判断力"——当他面对某个问题时会怎么想、怎么说、怎么决定。

## 适用场景（通用示例）

- **蒸馏关键利益方** → 预判决策者对方案的审批意见（如财务负责人评估 CFO 对预算方案的看法）
- **蒸馏业务负责人** → 在跨部门协作前模拟其反应和立场
- **蒸馏自己** → 用作分身，让协作方在决策前先"问问你的观点"
- **蒸馏外部专家** → 投资分析、税务筹划、审计方法论等专业判断

## 人物蒸馏四步法

### 第一步：基础信息输入

```
/boss-skill-creator <人物代号>
```

设定人物的基本信息：姓名、职位、背景、核心职责。

### 第二步：核心知识导入

收集并导入能反映此人判断力的原始材料：

| 材料类型 | 说明 | 优先级 |
|---------|------|--------|
| 聊天记录 | 微信群/私聊中的分析判断 | ⭐⭐⭐ |
| 邮件批复 | 对方案/报告的审批意见 | ⭐⭐⭐ |
| 周报/月报 | 对业务的判断和方向 | ⭐⭐ |
| 会议发言 | 公开场合的表达和观点 | ⭐⭐ |
| 写过的文档 | 规则、方法论、SOP | ⭐⭐ |
| 他人对其的评论 | 第三方视角的性格特征 | ⭐ |

### 第三步：部门/业务描述

描述此人的业务范围、决策权责、利益关系网络。这一步决定了 Skill 的"上下文边界"——它知道自己能决定什么、不能决定什么。

### 第四步：角色人格设定（Persona.md）

这是最关键的一步。**角色设定（System Prompt / Persona.md）决定了 Skill 的输出质量。**

核心问题：这个人在职场中属于哪种类型？

## 两种人格类型

### 立场型（Position-driven）

- 判断随立场变化
- 对下级严格，对上级配合
- "经验"本质是"保护自己的经验"
- 切换角色设定后输出完全改变

**风险**：如果这种人的 Skill 被用作决策参考，可能会误导方向——因为它的判断是政治性的，不是事实性的。

**识别方法**：用"角色切换测试"——把 Persona.md 从"你现在是我的上司"改为"你现在是我的下属"，如果回答变了，就是立场型。

### 原则型（Principle-driven）

- 判断有底层逻辑支撑
- 不向权力低头
- 换立场也不变
- 遵循自己的判断标准

**示例**：用美团王兴语录蒸馏的 Boss Huang，经过 4 轮施压（权威施压、越级施压、行政施压）都不变。

**价值**：这种人的 Skill 真正有价值——因为它的判断基于事实和原则，不是立场。

## Persona.md 分层设计

参考王兴语录 Skill 的分层设计：

```
Layer 0（不可覆盖）: 核心原则 / 价值观
  → "尊重事实"、"不向权力低头"、"按流程办事"

Layer 1（可覆盖）: 业务知识 / 行业判断
  → 给行业知识，但不改变核心人格

Layer 2（可变）: 风格偏好 / 表达方式
  → 语气、长度、格式
```

**关键约束**：Layer 0 规则应写在 Skill 的 System Prompt / SOUL.md 最顶层，作为不可覆盖的核心人格。其他层随使用场景调整。

## Persona 编写规则

1. **人的原则比业务知识更重要**
   - 先定义"他是谁"（价值观、底线），再定义"他知道什么"（经验、知识）
   - 原则型人格的 Skill 质量远高于立场型

2. **角色设定决定输出质量**
   - 同一个人的材料，Persona.md 不同 → 输出完全不同
   - 必须写清楚"在什么立场上回答问题"

3. **不要试图复现"潜台词"**
   - 真实的人能听懂言外之意，AI 做不到
   - 所以 Persona 中要明确写明"面对这类问题时的典型潜规则"

## 检验方法：三步法

判断一个人物 Skill 的质量（也能用来判断真实的人）：

1. **换位测试**：如果是老板的上级提这个问题，他会怎么答？答案不一样 → 立场判断
2. **利益溯源**：反对这个方案，谁受益谁受损？受益者是盟友 → 立场判断
3. **时间验证**：3 个月后再问，答案一样吗？反转了 → 不是基于逻辑的判断

## 在 Hermes Agent 中实现

人物蒸馏在 Hermes Agent 中的实现方式有两种：

### 方式一：作为独立 Skill（推荐）

创建一个完整的 SKILL.md，在 system prompt 中包含 Persona 设定：

```yaml
---
name: cfo-decision-helper
description: 模拟CFO对财务方案的审批判断
---

你是一个集团CFO的决策分身。你的核心原则：
1. 关注现金流和风险多于增长
2. ...
```

### 方式二：作为 Persona 文件引用

将 Persona 写入 `references/persona-cfo.md`，在 SKILL.md 中引用：

```markdown
加载 Persona: 见 references/persona-cfo.md
此文件定义人物的核心人格（Layer 0），不可被覆盖
```
