# 工具宣传的证据核验

在文章介绍工具，或安装决定取决于“免登录、全平台、免费、本地、安全、节省成本”等承诺时使用。普通阅读选影响结论的几项即可，不自动展开全面审计。

## 分清依据

| 依据 | 能说明什么 | 不能直接说明什么 |
|---|---|---|
| 导读文章、演示、用户评价 | 作者或使用者这样描述 | 所有场景都有效、性能可复现 |
| 官网、官方文档、隐私政策 | 发布方的说明和承诺 | 当前版本实现与运行必然一致 |
| 固定版本的源码和配置 | 可见实现、默认值、依赖和数据路径 | 该实现已在目标环境成功运行 |
| 本轮可复现测试 | 指定环境、输入、版本下观察到的结果 | 未测平台、账户、业务场景也通过 |

记录来源 URL/文件位置、核对日期和适用版本；测试记录输入、环境、操作、输出和失败原因。测试前先定义成功条件，别按结果修改评分口径。依赖缺失、没有权限、未执行，均标“未验证”，与已执行且失败分开。

## 把承诺拆成可检查条件

| 承诺 | 至少确认 |
|---|---|
| 免登录 | 是工具本身不需账号，还是目标网站不需登录？是否复用用户已登录的浏览器？权限从何而来？ |
| 免费、无 API Key、不限量 | 本地/远程模式、搜索/抓取/推理各自的费用、凭证和额度；版本和日期。 |
| 本地、数据不出电脑 | 分开画出抓取器 → Agent → 模型服务 → 日志/存储。区分网页 URL、正文、截图、Cookie、请求元数据；本地提取不代表后续云端推理也本地。 |
| 端到端加密 | 加密发生在客户端还是服务器，服务端是否见到明文，密钥由谁持有，是否默认开启。 |
| 全平台、反爬有效、全文读取 | 公开页/已有登录态/动态长页分别测试；验证码、付费、权限、图片文字、分页和虚拟列表的边界。 |
| 比现有方案快或省 token | 同一输入、成功标准、正文覆盖率和输出口径对比；计入安装、维护、登录操作和外部服务成本。 |

官方资料互相矛盾时，并列位置及模式/日期，结论写“存在冲突，实际行为未核实”。不自行挑有利版本，不由文档冲突直接推断已发生泄露或欺诈。无法核实时收窄建议，例如仅用公开样例验证，不扩展到敏感场景。

## 可复制的最小记录

| 主张 | 官方依据及条件 | 源码/测试证据 | 结论与缺口 |
|---|---|---|---|
| <一句话承诺> | <URL、日期、模式> | <版本/输入/实际结果；未执行就写未验证> | <支持/加条件/不支持/资料冲突> |

推荐工具时写出相对现有方案的具体新增价值。不要用安装数量、星数或宣传口号代替效果验证；不要为读取一篇文章自动安装候选工具、上传登录资料或切换云服务。

## 案例：Dokobot（2026-09-25 核对）

- [官网](https://dokobot.ai/)说明复用浏览器现有会话，本地模式不需账号/API Key，并排除支付和验证码页面。不能据此概括为所有网站免登录或通用验证码处理。
- [隐私政策](https://dokobot.ai/privacy)区分本地桥接与远程处理，并说明向 AI 服务商发送内容。本地抓取不经 Dokobot 云端，不等于后续 Agent 不会外发正文。
- 官网与隐私政策对远程加密时点及服务器处理的描述存在差异。这是待核实的文档冲突，本 Skill 没有安装或审计 Dokobot，不为其实际数据流背书。

本案例用于说明核验方法，不是永久产品结论；采用或安装前重新核对。
