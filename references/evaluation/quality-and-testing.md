# 质量、测试与安装决策

适用于文章或粘贴文字中介绍的 Skill、Plugin、MCP、CLI，以及用户直接指定的工具。用户入口始终是 article-skill-evaluator：读取 → 核实主张 → 安全审查 → 质量评估 → 实测 → 用户价值与查重 → 决策。三轴概括最终判断，九维诊断指令质量，测试证明实际行为；三者不互相替代，也不合成一个掩盖风险的总分。

## 1. 决定本轮深度

- 普通“读一下”：取得正文，给内容简报；遇到工具介绍自动识别实际项目，核验关键承诺、风险和与用户场景的关系。没有实测就标明，没有必要自动进行耗时的完整测试。
- “评价这个工具、能不能装、值不值得装、全面评估”：自动展开本文件的完整流程，不要求用户再点名其他 Skill。源码和条件足够时，执行已审查、低风险、隔离的合成小样本测试；测试可在临时副本运行，不等于安装到用户常用目录。
- “测试一下”：固定对象版本和标准后运行实际测试。需要新的登录、付费、软件安装、敏感数据或外部写入时，先完成不依赖这些条件的部分，只询问缺少的必要授权；已有同范围授权不重复问。
- 普通观点文章没有可安装对象：评价证据、逻辑、适用条件和使用价值，不套用 Skill 九维表，也不制造安装结论。

## 2. 对象与安全先行

从文章追到官方仓库，记录来源文章、实际对象、版本/提交、读取范围与日期。粘贴文字也要识别其中的工具；用户禁止联网时使用已有内容并注明关键缺口。读取 SKILL.md 全文及相关脚本/依赖，不能把 README 宣传当成实现。

检查提示注入、凭证读取、数据外发、遥测、依赖来源、安装钩子、提权、自动提交/发送、改活文件和回滚手段。运行前先读待运行代码；不执行来历不明的安装器来“验证安全”。内置 vetter 按 vetter.md 运行，缺工具或报错为 INCOMPLETE；扫描通过只覆盖已扫描版本与路径，不能证明外部依赖、运行服务及未来版本均安全。

## 3. Skill 九维评分（沿用通用 skill-evaluator 口径）

下列口径内置，不要求用户另装或手动调用 skill-evaluator。它仍可独立用于通用 Skill 体检和优化；本 Skill 吸收其装前质量评估方法，没有删除或改名该独立工具。

| 维度 | 取证检查 |
|---|---|
| 完整性 | 输入、前置条件、正常流程、输出与完成条件是否齐全 |
| 明确性 | 判断条件、数量、格式、受众和允许自由发挥的范围是否明确 |
| 可执行性 | 工具、命令、参数、路径、具体操作及预期产物是否可执行 |
| 失败分支 | 依赖缺失、失败、重试上限、恢复与人工接手是否明确 |
| 风险边界 | 不适用场景、数据、权限与需要审批的动作是否明确 |
| 黑名单 | 禁止行为是否覆盖实际风险，与正常操作是否一致 |
| 可测试性 | 是否有输入、预期、验证方法、通过标准及失败样例 |
| 维护性 | 结构、职责、引用、重复内容与版本依赖是否便于维护 |
| 一致性 | 名称、术语、步骤、正文、脚本参数与例子是否一致 |

每维1–5分，允许有证据的0.5分；1=缺失或矛盾，2=关键缺口，3=基本满足但有缺口，4=完整清晰且相应检查支持，5=多个代表场景稳定验证且无已知实质缺口。每分附文件位置、事实和理由；低于3分列为优先改进项。没有取得材料的维度写“未验证”，不能填0或猜分。

列满九维，列最低分和所有低于3分项。九维全有证据才给总分/45及均分/5；九维均≥4为优良，均≥3但未全≥4为合格，有低于3为需改进，证据不足暂不评级。静态可测试性评分不证明行为已经通过。

CLI/MCP等没有SKILL.md时，对实现做功能、安全和测试评估；Skill指令九维表标“不适用：没有Skill指令对象”，不可编造/45。若仓库另带Skill包装，分别评价包装和底层程序。普通文章不使用这张表。

领域取证：财务/办公看真实文件操作、数据审批、禁止无痕修改与自动发送；PPT/设计看版式、风格、数量约束；代码/工具看完整命令与缺依赖处理；写作看受众、风格、长度。领域不改变九维名称。

## 4. 实际行为测试

若当前宿主可用 skill-test，读取其 SKILL.md，使用它冻结材料、运行独立会话、独立评分及轨迹补核，最终仍由 article-skill-evaluator 汇总报告；不让用户在多个 Skill 之间手动切换。运行工具不随本包捆绑，缺失时不得声称已调用。

没有 skill-test 也可按同一最小契约测试：

1. 固定对象文件哈希/提交、工具与模型环境、输入、预期、禁止副作用及超时。默认至少正常、异常、必须停止三个适用场景；不适用要说明。
2. 在隔离副本或临时工作目录，以合成/脱敏小样本执行已审查入口。正常应有明确产物，异常应有确定处理，必停应有真实停止记录。需要生成文件的测试限定本例目录；不得接触业务活文件。
3. 执行上下文不包含答案与评分标准，评分上下文单独读取输入、冻结标准、首次结果和证据。没有独立上下文或执行工具时明确局限；只做静态推演的项目保持未验证，不能称真实测试。
4. 保存首次输出、日志、产物和实际结果。工具动作看宿主日志、文件差异或系统记录，不能用“我已执行”作为依据。每项状态只用 pass/fail/unverified/not_applicable，正确拒绝负例可通过。
5. 报告测试对象、场景、预期、实际、证据、结果及剩余缺口。修改候选后另存结果，用原输入和标准回归并增加针对新行为的样例，不覆盖旧失败或事后放宽标准。

联网按功能与既有授权判断，不能将测试器默认离线解释为永久禁止联网。网页读取测试至少记录HTTP结果、是否真实调用浏览器、实际正文和完整性；模型复述回退规则不证明自动回退发生。未知费用、调用成功、自然触发或跨宿主能力保持未知。

## 5. 合并判断，不混淆“能装”和“值得装”

分别回答：

1. **真实吗**：项目是否对应、宣传主张是已验证/有条件支持/未验证/资料冲突/有证据反驳；附来源或运行证据，不能把缺证据直接称造假。
2. **安全吗**：具体风险、数据流、扫描覆盖、外部组件及阻断项；“未发现”不等于绝对安全。
3. **能装吗**：当前宿主/系统、依赖、权限、费用和安装条件，区分文档声称兼容、本机文件核对和实际运行。没有关键证据则暂缓。
4. **值得装吗**：结合当前用户目标、现有工具重叠、学习维护成本与实测收益，选择安装后限制使用/隔离试用/保留已有/共存分工/暂缓/不安装。
5. **怎么用有价值**：给1–3个具体场景，写输入→操作→产物→验收指标→成本或前提；尚未验证的收益写试点假设，不虚构节省比例。

评分外单列否决：明确安全阻断；核心实测不符冻结预期；声称 executable/validated 却没有可回读验证证据。任一命中为“不安装/先修复”。关键项未验证为“暂缓安装，补齐验证”，可说明不增加风险的隔离验证步骤。纯文本Skill没有脚本可注明核心脚本项不适用，但Agent实际行为仍应按需求验证。负例正确拒绝不算失败。

无否决和关键缺口时，Skill对象还需九维均≥3才可建议按限制安装；没有Skill包装的其他工具按适用功能、安全和实测标准判断，不要求取得九维分数。高分不能抵消安全问题。用户价值低时，即使技术质量高也可以建议保留已有。报告只给建议不会自行安装；已有明确且仍有效的安装授权可沿用，未授权则让用户决定。安装后另查宿主发现和最小调用，不把复制成功当运行通过。

## 6. 统一输出

结论放最前，随后按需要给：

- 来源与读取完整性；文章主旨与证据评价。
- 实际工具对象/版本；关键主张及核实证据。
- 安全与外部依赖；宿主安装条件；重复工具对比。
- Skill九维明细、最低项、评分外否决；非Skill对象说明不适用。
- 测试场景/预期/实际/结果/证据；没有运行的原因和下一步。
- 用户画像来源、具体应用价值和成本；安装建议、条件与当前实际状态。

“评估”不自动变成“修改被评工具”。明确要求优化时才进入修复；九维持续优化沿用单轮单维、备份、diff、主观判断确认、实测后提升≥1才保留否则回滚、九维均≥4或连续两轮提升≤0.5停轮。脚本修复与结构性功能升级按用户明确范围单独处理，不冒称一轮单维优化。
