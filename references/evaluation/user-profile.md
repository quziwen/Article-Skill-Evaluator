# 用户画像获取方法论（评估校准基准）

评估模式轴 B"是否适合你"必须落到**当前用户的实际画像**上，不能笼统说"都能用"，也不能使用项目作者自己的画像（见 [user-profile.example.md](user-profile.example.md)，那只是作者示例，不代表你）。

## 一、如何获取当前用户的画像（按优先级）

评估"适合我吗"之前，先按以下顺序获取用户画像，**取第一个能拿到信息的来源**：

1. **Agent 环境用户描述**：读取当前环境的 AGENTS.md / CLAUDE.md / 用户系统提示中的身份、角色、偏好描述（例如 `~/.agents/AGENTS.md`、项目根目录的 `AGENTS.md`、`CLAUDE.md`）。
2. **用户显式提供**：如果用户在本次对话中已说明身份/行业/目标（如"我是财务，关注核算/审计"、"我在做 PPT"），直接采用。
3. **记忆/知识库**：如当前 Agent 有用户记忆（记忆库、用户档案、个人偏好文件），读取其中的稳定偏好。
4. **一句话确认**：以上都没有时，用一句话问用户："这个工具主要用于你的什么场景？"（例如：行业/岗位、常用软件、主要目标）。不要在评估报告中大量追问，一次问清即可。
5. **通用默认**：用户不回答且无任何来源时，使用下方"通用默认画像"，并在报告中明确标注：**"基于通用默认画像评估，如需精准适配请提供你的行业/场景"**。

## 二、通用默认画像（无信息时的兜底）

当无法获得用户具体画像时，使用以下中性默认（不预设行业/公司/设备）：

- 目标：工具应为用户实际工作带来效率提升，能解决真实问题。
- 学习与效率：用户重视学习价值与可复用产出（文档、表格、知识管理）。
- 偏好：开源、零付费、可本地运行优先；付费 / API key / 闭源需要专门说明理由。
- 平台：优先考虑用户当前所用操作系统（Windows/macOS/Linux 未知时标出兼容性，不假设）。
- 安全：任何让 Agent 执行敏感动作（修改文件不留痕、自动提交/发送、读取数据外发、执行宏/脚本、改权限）的工具，必须提示风险与可审计性，不默认自动执行。

## 三、画像应用规则

- 轴 B 结论必须落到画像：高契合（直接服务其工作/学习目标）、部分契合（说清哪部分用不上）、不契合（与其目标无关）。
- 画像信息不足时，轴 B 给"暂无法判定（缺画像）"，不要臆测用户身份。
- 使用通用默认画像时，报告轴 B 结论标注"通用假设"。

## 四、用户画像应包含的维度（模板）

拿到用户信息后，按以下维度组织画像（填入实际内容）：

- **身份与角色**：行业 / 岗位 / 组织角色
- **工作主线**：核心业务领域、常用工具链
- **学习兴趣**：主动学习的领域（如 AI、设计、音视频等）
- **工作流与环境**：知识库、设备、常用 Agent、高频任务
- **硬性偏好**：开源/付费、平台、成本敏感度
- **安全与合规视角**：是否有审计/内控要求、对自动化的审慎程度
