# 评估对象的只读取证路线

目标是取得文章实际介绍的项目及其一手文件，不是突破站点访问控制。

## URL 处理

- 保留决定资源身份、权限或版本的查询参数，不要机械删除整个 query。
- 可以在确认不影响资源后移除 `utm_*` 等纯跟踪参数。
- 不向第三方服务发送带签名、token、内部域名、个人标识或授权信息的 URL。
- 本地执行器只接受公网 HTTP(S) 地址，并阻断凭证、localhost、私网、链路本地、保留地址和不安全重定向。

## 从导读壳定位真实项目

文章、帖子和聚合页不是可安装物。先从已取得的可见正文中查找官方仓库、官网、发布页或包注册页；找不到时，用项目名和作者名搜索官方来源。报告必须同时写明“来源文章”和“实际评估对象”。

对 GitHub 项目，优先读取：

1. 仓库主页和默认分支。
2. `README.md`、`SKILL.md`、`plugin.json` 或 marketplace 声明。
3. `package.json`、依赖锁文件、发布记录和许可证。
4. 与权限、网络、命令执行、安装和数据流有关的源码。

不得凭导读文章的功能宣称替代仓库证据。

## 普通反爬与动态页面

依次尝试专用只读连接器/API/CLI、包内 HTTP 执行器、当前环境已安装的临时 Playwright，以及受控桌面浏览器。每次切换必须能带来新增证据；遇到验证码、登录墙、宿主策略拒绝或无授权付费墙时停止。

公开网页存档只可用于核对历史上公开过的内容，并应标注存档时间和来源；不能用存档、代理、缓存、AMP 或机器人身份规避当前访问权限。具体付费内容规则见 `../enhance/paywall-bypass.md`。

## 失败处理

拿不到真实正文或仓库时，不做确定性评估。写明已经尝试的路线和阻断类型，请用户提供其有权分享的 README、ZIP、PDF、导出文件或官方仓库地址。搜索摘要只能作为定位线索，不能冒充原文。
